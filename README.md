# Cumbria Peptides — e-commerce & order management

A UK peptide storefront with an admin dashboard for running manual fulfilment. Customers browse,
add items to their basket and check out; the owner gets notified, packs each order by hand using
a guided checklist and printable packing slip, and marks it shipped with tracking.

> Brand name, logo and contact details live in `src/config/site.ts`.

## What's live now

**Storefront:** `/`, `/shop`, `/product/:slug`, `/cart`, `/checkout`, `/order-confirmed`, `/about`,
`/contact`, `/shipping`, `/refunds`, `/terms`, `/privacy`, `/disclaimer`, plus a 404 page, an error
page, `sitemap.xml` and `robots.txt`.

Products, prices and stock are read from **Netlify Database** (Postgres) through server functions.
Checkout sends only variant IDs and quantities; the server re-prices the basket from the database,
locks the stock rows, decrements stock and saves the order in one transaction. Orders are numbered
`ORD-10001`, `ORD-10002`… from a Postgres sequence. No online payment is taken yet: orders are
saved with payment `PENDING`.

**Admin** (Netlify Identity sign-in at `/admin/login`):

- `/admin/products` — live catalogue with prices and stock, and product image upload
- `/admin/data` — demo-data counts, "Load sample data" and **Remove all demo data**
- `/admin/dashboard`, `/admin/orders`, `/admin/orders/:orderNumber` — the packing workflow, still
  on fictional sample data (`src/data/fixtures.ts`) until the orders milestone

## Tech

- TanStack Start (React 19, file-based routing, SSR) on Netlify
- Tailwind CSS 4, Instrument Serif and IBM Plex
- Netlify Database (Postgres) with Drizzle ORM — `db/schema.ts`, migrations in
  `netlify/database/migrations/`
- Netlify Identity (admin sign-in and roles), Netlify Blobs (product images), Netlify Image CDN
  (all imagery), Netlify Forms (contact form and order emails)
- Slack order notifications via an outbox with retries
- Planned: Stripe, Twilio, Google Sheets and transactional email

## Run locally

```bash
pnpm install
netlify dev --port 8889
```

`netlify dev` emulates the database (a local Postgres-compatible PGlite instance in `.netlify/db`),
Blobs, Identity and the Image CDN. Apply migrations to the local database with:

```bash
netlify db migrations apply
```

> If `NETLIFY_DB_URL` is set in your shell, the `netlify db` commands use that database instead of
> the local one. Unset it for local work. The local emulator runs all connections through one
> session, so it can't be used to test concurrent transactions; use a real Postgres for that.

Copy `.env.example` to `.env` for any local integration credentials.

## Database

- **Change the schema** in `db/schema.ts`, then `pnpm db:generate --name <what_changed>`. Commit
  the generated folder. Never edit or delete a migration that has been deployed; add a new one.
- **Migrations are applied by Netlify** on every deploy (production right before publishing;
  deploy previews on their own database branch with a copy of production data).
- **Money** is stored as integer pence. **Order numbers** come from `order_number_seq` (starts at
  10001, never reused, unique constraint on `orders.number`). Demo orders use a separate
  `demo_order_number_seq` (`ORD-900001`…) so real numbering stays contiguous.
- **Stock** is decremented when an order is placed. Each decrement writes an
  `inventory_movements` row; a unique index stops the same order decrementing twice, and a CHECK
  constraint stops stock going below zero.
- **No card data** is stored. `payments` keeps only a provider reference.

### Demo data

Rows created by the demo seed have `is_demo = true`. Nothing else ever sets that flag, and real
rows are never reclassified as demo.

- Load: `/admin/data` → **Load sample data**, or `pnpm db:seed-demo` with `NETLIFY_DB_URL` set (the
  script refuses to write to production unless `ALLOW_PRODUCTION_SEED=1`).
- Remove: `/admin/data` → **Remove all demo data**, then type `REMOVE DEMO DATA`. Runs in one
  transaction, deletes only flagged rows, keeps any flagged row a real record still references, and
  writes an audit-log entry.

## Product images

Uploads (JPEG, PNG, WebP or AVIF, up to 5 MB, type checked from the file contents) go to the
`product-images` Netlify Blobs store under content-addressed keys. The key is saved on the product
in the database. `/media/products/<key>` serves the blob with immutable caching, and the storefront
requests it through the Image CDN (`/.netlify/images?url=/media/products/<key>&w=…`), which treats it
as a same-site source image. Products without an upload use their bundled image in `public/img`.

## Environment variables

| Variable | Where | Required | Purpose |
| --- | --- | --- | --- |
| `NETLIFY_DB_URL` | Set by Netlify automatically | Yes (automatic) | Postgres connection. Don't set it yourself on Netlify. |
| `SLACK_WEBHOOK_URL` | Netlify env vars | One Slack option | Incoming-webhook URL for order notifications |
| `SLACK_BOT_TOKEN` + `SLACK_CHANNEL_ID` | Netlify env vars | One Slack option | Bot token (`chat:write`) and channel ID; the bot must be in the channel |
| `ALLOW_PRODUCTION_SEED` | Your shell only | No | Lets `pnpm db:seed-demo` write to production |

Blobs and Identity need no variables. Mark Slack values as secrets in Netlify.

## Admin access

1. Netlify → **Project configuration → Identity**: set registration to **Invite only**.
2. **Identity → Invite users**, invite the owner's email, and accept the invite from the email.
3. Open the user in the Identity list and add the role `owner` (or `admin`, `packer`, `viewer`).
4. Sign in at `/admin/login`.

Owners and admins can upload images and manage demo data. Packers and viewers can view.
